# Legal, Security & Compliance

This is the single entry point for CDS's legal, licensing, security, support,
and regulatory-compliance documentation. Each linked document remains the
source of truth for its own topic; this page only indexes them so they don't
need to be discovered individually across the repository root and `docs/`.

## License

- [`LICENSE`](LICENSE) — Apache License 2.0, the terms under which CDS is
  distributed.

## Community & Conduct

- [`CODE_OF_CONDUCT.md`](CODE_OF_CONDUCT.md) — expected behavior for anyone
  participating in the project.

## Security

- [`SECURITY.md`](SECURITY.md) — how to report a vulnerability, the
  coordinated disclosure process, and the intake channels.
- [`docs/security-support-policy.md`](docs/security-support-policy.md) — which
  releases receive security fixes, how long a release stays supported after
  being superseded, severity-based fix delivery targets, and the emergency
  release path.
- [`docs/security-compliance-categories.md`](docs/security-compliance-categories.md)
  — how each rule in the bundled security rule-set maps to a compliance
  control category.

## Support

- [`SUPPORT.md`](SUPPORT.md) — how to get help, what to include in a bug
  report, and response-time expectations.
- [`docs/support-policy.md`](docs/support-policy.md) — supported host
  operating systems and known platform-specific limitations (distinct from
  the release security-support policy above).

## Regulatory Compliance

- [`docs/cra-scope-decision.md`](docs/cra-scope-decision.md) — the project's
  current EU Cyber Resilience Act (CRA) scope and accountable-role
  determination, and the conditions under which it must be reassessed.
- [`docs/cra-incident-runbook.md`](docs/cra-incident-runbook.md) — the
  operational runbook for CRA Article 14 actively-exploited-vulnerability and
  severe-incident reporting triggers.

Nothing on this page constitutes legal advice. See
[`docs/cra-scope-decision.md`](docs/cra-scope-decision.md) for that
