Recall-biased review

Running the feature exposed two silent convergence failures

  • Full-table write amplification: the same snapshot moved MAX(snapshot_loaded_at) from 06:19:42 to 06:55:35.
  • Stale mounted code: Helm revision 11 updated the ConfigMap but retained a 48-minute-old Dagster pod.
  • Provisioning drift: existing database URIs were not reconciled, and chart matching was name-only.
Root-cause hardening

The fixes make convergence explicit

  • workdirs/dagster/tender_analytics.py:173 updates only rows that are distinct.
  • cli/k8s_renderer.py:352 puts mounted-data checksums in pod templates.
  • scripts/tender/provision-dashboard.py:302 reconciles the database connection.
  • scripts/tender/provision-dashboard.py:381 scopes chart identity to its dataset.

Post-fix evidence: revision 12 created pod cds-dagster-user-code-7bb989c56b-z8z5t, and the unchanged load preserved the timestamp exactly.
